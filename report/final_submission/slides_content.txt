s4: problem statement and motivation
IELTS learners need frequent writing and speaking practice, but consistent expert feedback is limited by cost and availability.
Current preparation is often fragmented across separate apps/tools for writing, speaking, and progress tracking.
Our motivation is to provide one practical, AI-assisted platform for both writing and speaking workflows.

s5: why this problem matters
Why this matters:
- Delayed feedback slows skill improvement.
- Learners need repeated mock practice under realistic conditions.
- Teachers/tutors cannot always provide instant individualized review.
- A unified digital platform improves accessibility and learning consistency.

s10: solution overview
Solution Overview
IELTS Mock Examiner is a web platform that combines:
- Writing task submission and AI-assisted evaluation.
- Speaking practice workflow with audio processing support.
- User authentication and module-oriented navigation.
- Configurable runtime settings for model and timing behavior.

s11: system architecture
System Architecture
- Frontend: React + Vite + TypeScript UI.
- Backend: Django + DRF + Channels.
- API groups: /api/, /api/auth/, /api/writing/, /api/speaking/.
- Data/runtime: SQLite path config, media/cache mounts.
- Deployment: Docker Compose orchestrating backend and frontend.

s12: backend modules
Backend Module Breakdown
- core: base/health endpoints and foundational services.
- accounts: authentication endpoints and token-based access.
- writing: writing topics, submissions, and evaluation pipeline.
- speaking_app: speaking endpoints and realtime interaction logic.
- ai_services: Gemini, STT/TTS, VAD and prompt utilities.

s13: writing module flow
Writing Module Flow
1. User selects writing task and submits essay.
2. Backend validates and forwards request to evaluation pipeline.
3. Gemini-configured service generates feedback and scoring structure.
4. Response is returned to frontend for user review.

s14: speaking module flow
Speaking Module Flow
1. User starts speaking session from frontend.
2. Audio is segmented using VAD-based logic.
3. STT configuration is used for transcription.
4. TTS configuration is used for spoken responses/interaction support.
5. Backend returns structured responses for continued session flow.

s15: tools and technologies used
Tools and Technologies Used
- Backend: Python, Django, Django REST Framework, Channels
- Frontend: React, Vite, TypeScript, Tailwind CSS, shadcn/ui
- AI/Speech: Gemini model config, Whisper model path config, Kokoro model path config, WebRTC VAD logic
- DevOps: Docker, Docker Compose

s16: environment and configuration
Environment and Configuration
- Config through `backend/.env` and compose environment variables.
- Model and timing parameters are externally configurable.
- SQLite path configured via `SQLITE_PATH`.
- Health check endpoint supports startup coordination.

s17: development process
Development Process
- Iterative development by feature modules.
- API-first backend implementation, then frontend integration.
- Continuous local validation through containerized stack.
- Incremental refinement of prompts, audio timing, and routing behavior.

s18: quality and validation approach
Quality and Validation Approach
- Route/module verification for auth, writing, and speaking APIs.
- Integration checks for backend/frontend connectivity.
- Runtime checks for container startup order and health readiness.
- Functional review of user flows in writing and speaking pages.

s19: challenges encountered
Challenges Encountered
- Coordinating multiple AI/speech components in one workflow.
- Maintaining smooth speaking flow with timing and silence detection.
- Keeping configuration flexible without hardcoding model/runtime values.
- Ensuring reliable local deployment across services.

s20: resolutions
Resolutions
- Modularized backend into focused apps for separation of concerns.
- Exposed timing and model parameters via environment variables.
- Added health-check-based dependency control in Docker Compose.
- Standardized API routes for predictable frontend integration.
